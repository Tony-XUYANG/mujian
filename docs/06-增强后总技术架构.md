# 幕间增强后总技术架构

## 1. 架构目标

在纸面四表和 Spring Boot + React + MySQL 基础上，用最少的额外组件完成红果式短剧核心闭环：内容发现、播放、互动、进度回访和后台维护。当前架构保持单体、同源和可演示，避免为尚未存在的分集、支付或推荐系统引入空壳服务。

## 2. 组件视图

```text
手机/桌面浏览器
  ├─ React 19 + TypeScript + Vite
  ├─ PWA manifest / Service Worker
  ├─ App 壳缓存 / 离线片库 Cache Storage
  └─ 离线片库元数据 localStorage
          │ same-origin /api
Spring Boot 3.5.6
  ├─ AuthController + JWT
  ├─ DramaController
  ├─ EngagementController
  ├─ AdminController
  ├─ DramaRepository / JdbcTemplate
  └─ SecurityConfig / BCrypt / validation
          │ JDBC
MySQL 8.4
  ├─ user / drama
  ├─ user_like / user_favorite
  └─ watch_history / drama_comment
```

## 3. 数据设计决策

原始四表继续作为核心模型。`watch_history` 用 `(user_id, drama_id)` 唯一约束表达“每人每部一条进度”；`drama_comment` 使用用户和短剧外键，并按短剧和时间建立索引。点赞、收藏和历史删除短剧时级联清理，避免孤儿数据。

后续分集扩展建议新增：

- `drama_episode(id, drama_id, episode_no, title, video_url, duration_sec, status)`。
- `drama_release(drama_id, episode_id, publish_at)` 或直接使用剧集发布字段。
- 将 `watch_history` 的唯一键从短剧维度迁移为用户/剧集维度，并保留短剧汇总进度。

该迁移应在真正需要全集连播时实施，不在当前单视频演示中提前复杂化。

## 4. 认证与安全

注册密码使用 BCrypt，JWT 使用 HS256 和配置化密钥，默认有效期 8 小时。角色从 JWT `role` 转换为 Spring Security 的 `ROLE_USER/ROLE_ADMIN`。`/api/admin/**` 只允许管理员；公开读取接口允许匿名；其他接口要求认证。

服务端做 Bean Validation、URL 协议和本地资源路径校验。生产部署必须替换演示数据库密码、JWT 密钥和管理员密码，关闭示例账号初始化并启用 HTTPS。当前仓库配置只用于本地演示。

## 5. 关键时序

### 播放和进度

1. 前端打开播放器，读取 `GET /api/dramas/{id}` 和评论。
2. 首次 `play` 请求 `POST /api/dramas/{id}/view` 增加播放计数。
3. 播放中约每 15 秒、`pause`/`ended`/关闭时请求 `PUT /api/dramas/{id}/progress`，服务端裁剪进度并执行 Upsert。
4. “继续观看”调用 `GET /api/me/history`；登录用户详情返回个人进度，播放器加载元数据后恢复位置。

### 互动

前端调用 PUT/DELETE；服务端先确认短剧存在，再插入或删除关系；联合唯一冲突被视为幂等成功，最后返回最新计数和状态。

### 评论

游客读取 `GET /comments`；用户提交 `POST /comments`，服务端校验长度并写入，返回昵称和创建时间。下一阶段增加审核状态和举报接口。

## 6. PWA 与原生演进

当前 PWA 使用 `standalone`、竖屏方向和 App 壳缓存。构建阶段生成 Vite 资源清单，Service Worker 安装时预缓存 HTML、JS、CSS；动态 `/api/` 不缓存。用户主动下载的视频写入独立媒体缓存，Service Worker 对完整请求和 Range 请求返回缓存内容，离线片库通过本地元数据列出短剧。版本升级只清理旧 App 壳，不清理媒体；浏览器存储回收后内容可能消失。断网导致认证请求失败时保留会话 Token，重新联网后恢复用户信息。

若需要应用商店包，推荐在接口和前端稳定后引入 Capacitor：复用 React 构建产物和同源 API，补充 Android/iOS 项目、图标、权限、签名、深链和发布流水线。需要 Android SDK、iOS 工具链及真实设备验收，当前环境没有这些条件。

## 7. 质量与运维

当前通过构建、真实 HTTP、Service Worker 缓存模拟和浏览器操作验收；后续应补充 Controller 集成测试、数据库迁移工具、结构化日志、错误追踪、慢 SQL 监控、对象存储/CDN、备份和恢复演练。内容量增长后再把搜索、推荐和播放统计拆分为独立能力。
