## 3. 数据设计决策

原始四表继续作为核心模型。`watch_history` 用 `(user_id, drama_id)` 唯一约束表达“每人每部一条进度”；`drama_comment` 使用用户和短剧外键，并按短剧和时间建立索引。`user_profile` 用用户主键保存头像和主页背景地址。点赞、收藏和历史删除短剧时级联清理，避免孤儿数据。

评论治理使用两张独立表：`drama_comment_report` 记录举报人、白名单原因和处理状态，`(comment_id,user_id)` 联合唯一保证重复举报幂等；`drama_comment_moderation` 保存评论当前 `VISIBLE/HIDDEN` 状态与管理员处理记录。评论读取过滤隐藏状态，隐藏不物理删除，恢复只更新状态。

2026-10-01 分集扩展已落地：

- `drama_episode(id, drama_id, episode_no, title, video_url, create_time)`。
- `drama_series` 保存状态/计划集数；`user_follow` 保存独立追剧关系。
- `episode_progress` 按用户/分集保存秒数，`watch_history` 保留用户/短剧汇总。

启动迁移使用 `drama_series` 标记处理过的旧剧，将旧进度映射到首集。发布链路已用 3 张独立表落地，不给原表增加易遗漏的迁移列。详细锁顺序、幂等与接口见 [当前技术架构](04-当前技术架构.md)。后续引入 Flyway 管理版本迁移，为整剧首播建立内容生命周期，保留分集排期兼容。

发布可靠性下一步：增加尝试次数、最近失败原因、退避/死信、人工重试与监控指标；大规模订阅由 Outbox 事务事件 + 消费者分批写通知，避免发布事务一次写大量收件人。独立 draft 状态隔离草稿/预览；消息按事件类型和事件 ID 去重，以支持改期/取消通知。日历/预约改用游标分页，信箱从 offset 演进到 ID 游标；App 开启期间可用 SSE，关闭后提醒需 Web Push 或原生通知服务、权限和设备 Token 生命周期。当前实现不依赖这些未来服务。

推荐链路当前不新增用户画像表：`GET /api/recommendations` 复用 `user_follow`、`user_favorite`、`watch_history` 和 `drama`，在 Repository 中按分类聚合行为权重，返回分数和中文理由。前端 `RecommendationFeed.tsx` 以单列卡片呈现并直接复用播放器入口。后续若内容量增长，再将行为事件、曝光/点击日志、标签和实验分组拆成独立推荐服务；当前规则需要保持可解释、可回归和容易人工调整。

## 4. 认证与安全

注册密码使用 BCrypt，JWT 使用 HS256 和配置化密钥，默认有效期 8 小时。角色从 JWT `role` 转换为 Spring Security 的 `ROLE_USER/ROLE_ADMIN`。`/api/admin/**` 只允许管理员；公开读取接口允许匿名；其他接口要求认证。

服务端做 Bean Validation、URL 协议和本地资源路径校验。生产部署必须替换演示数据库密码、JWT 密钥和管理员密码，关闭示例账号初始化并启用 HTTPS。当前仓库配置只用于本地演示。

## 5. 关键时序

### 播放和进度

1. 前端打开播放器，读取详情、分集目录和评论，根据 `resumeEpisodeId` 选择最近观看集。
2. 首次 `play` 请求 `POST /api/dramas/{id}/view` 增加播放计数。
3. 播放中约每 15 秒及暂停、结束、切集、关闭、隐藏页面时请求分集进度接口。前端请求排队，服务端校验归属后在事务里写分集进度及历史汇总；旧进度接口继续映射到首集。
4. “继续观看”调用 `GET /api/me/history`；登录用户详情返回个人进度，播放器加载元数据后恢复位置。

### 个人资料图片

1. 用户在“我的”页选择头像或背景图片，在 `ProfileImageEditor.tsx` 的 Canvas 预览中拖动、缩放和调整位置；确认后编码 JPEG，以 `multipart/form-data` 发送到受保护的资料接口，取消不会上传。
2. 服务端校验图片类型、文件大小和像素总量，缩放为 JPEG 后写入配置的 `UPLOAD_DIR`。
3. `user_profile` 使用用户主键 Upsert 地址；旧的本地上传文件在替换成功后删除，清理失败记录日志而不影响新资料保存；页面使用同源 `/uploads/` 地址即时回显。

昵称通过 `PATCH /api/auth/profile` 修改，服务端使用 JWT 身份，拒绝空白、超长和控制字符，忽略客户端提交的角色或其他用户 ID。前端个人主页独立为 `Profile.tsx`，复用收藏和历史接口实现标题搜索、管理确认和逐条移除。上传超限/文件缺失和网络失败提供中文提示，支持重试。

### 互动

前端调用 PUT/DELETE；服务端先确认短剧存在，再插入或删除关系；联合唯一冲突被视为幂等成功，最后返回最新计数和状态。

### 评论

游客读取 `GET /comments`；用户提交 `POST /comments`，服务端校验长度并写入，返回昵称和创建时间。登录用户提交 `POST /comments/{commentId}/reports` 举报；管理员使用 `GET /api/admin/comment-reports` 查询，使用 `POST /api/admin/comment-reports/{id}/resolve` 传入 `HIDE` 或 `DISMISS` 处理，并通过 `POST /api/admin/comments/{id}/restore` 恢复隐藏评论。服务端校验评论归属、举报原因和管理员角色，所有操作返回中文可读错误。

## 6. PWA 与原生演进

当前 PWA 使用 `standalone`、竖屏方向和 App 壳缓存。构建阶段生成 Vite 资源清单，Service Worker 安装时预缓存 HTML、JS、CSS；动态 `/api/` 不缓存。用户主动下载的视频写入独立媒体缓存，Service Worker 对完整请求和 Range 请求返回缓存内容，离线片库通过本地元数据列出短剧。版本升级只清理旧 App 壳，不清理媒体；浏览器存储回收后内容可能消失。断网导致认证请求失败时保留会话 Token，重新联网后恢复用户信息。

若需要应用商店包，推荐在接口和前端稳定后引入 Capacitor：复用 React 构建产物和同源 API，补充 Android/iOS 项目、图标、权限、签名、深链和发布流水线。需要 Android SDK、iOS 工具链及真实设备验收，当前环境没有这些条件。
