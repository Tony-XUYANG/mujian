# 幕间当前技术架构

## 1. 总体结构

```text
浏览器/PWA
   │ 同源 HTTP
React 19 + TypeScript + Vite
   │ /api
Spring Boot 3.5.6 + Java 21
   │ JdbcTemplate / 参数化 SQL
MySQL 8.4
```

生产构建后的 React 静态文件复制到 Spring Boot 的 `static/`，因此演示服务只需要 Java 和本地 MySQL。开发时 Vite 代理 `/api` 到后端。

## 2. 后端分层

- `AuthController`：注册、登录、当前用户和昵称修改。
- `DramaController`：公开列表、详情、播放计数、点赞和收藏。
- `EngagementController`：观看历史、进度、评论。
- `EpisodeController`：公开分集、分集进度、追剧列表/关系、管理员分集 CRUD 与状态校验。
- `EpisodeMigration`：启动时幂等迁移旧单视频和观看进度；已迁移内容不会被重新初始化。
- `AdminController`：管理员统计和短剧 CRUD。
- `ProfileMediaController`：用户头像/主页背景上传、图片缩放和资源地址返回。
- `DramaRepository`：列表、详情、过滤和互动计数 SQL。
- `SecurityConfig`：无状态 JWT、角色转换、BCrypt、401/403 JSON 错误。
- `schema.sql`：表、索引、联合唯一约束和外键。

所有 SQL 使用参数绑定；管理员资源 URL 在 Controller 层通过 URI 规则校验；数据库外键使用 `ON DELETE CASCADE`。

## 3. 数据模型

核心表为 `user`、`drama`、`user_favorite`、`user_like`。增强表为：

| 表 | 作用 |
| --- | --- |
| `watch_history` | 每个用户和短剧一条记录，保存进度、总时长、最近观看时间 |
| `drama_comment` | 保存短剧评论，与用户和短剧建立外键 |
| `user_profile` | 用户头像和主页背景地址，一对一外键关联 `user` |
| `drama_series` | 一对一连载状态、计划总集数；同时标记该剧已迁移 |
| `drama_episode` | 分集视频及标题，`(drama_id,episode_no)` 唯一 |
| `episode_progress` | `(user_id,episode_id)` 主键，秒数、时长与微秒级观看时间 |
| `user_follow` | `(user_id,drama_id)` 主键，与收藏独立 |

当前共 11 张表。旧表不做破坏性改造：`watch_history` 保留每人每剧的汇总进度，新播放器写入分集进度时在同一事务更新汇总；旧进度接口映射到第一集。详情按最近分集观看时间返回 `resumeEpisodeId/No`。删除某集会级联清理分集进度并重算历史；删除全剧级联清理所有关系。

分集写入、改集、删集和删历史通过短剧行锁串行化，集号还有数据库唯一约束。前端将一次播放会话中的保存请求排队，每个视频组件绑定固定分集，卸载时保存旧集快照，避免快速切集把进度写到新集。跨设备同时观看采用服务端最后到达的保存结果，暂未做多设备冲突合并。

关键索引：用户名唯一、点赞/收藏/历史联合唯一、分类索引、评论 `(drama_id, create_time)` 索引。

## 4. API 契约

公开接口：`GET /api/health`、`GET /api/dramas`、`GET /api/dramas/{id}`、`GET /api/dramas/{id}/comments`、`POST /api/dramas/{id}/view`。

认证接口：`POST /api/auth/register`、`POST /api/auth/login`、`GET /api/auth/me`。

个人资料接口：`POST /api/auth/profile/avatar`、`POST /api/auth/profile/background`，使用 `multipart/form-data` 上传图片，登录后可用。

`PATCH /api/auth/profile` 接收 `{ "nickname": "新昵称" }`，经长度、空白和控制字符校验后，仅更新 JWT 对应用户并返回当前资料。账号和角色不可从该接口修改。超大文件返回 413，缺失文件和不可解码图片返回 400，均带中文错误信息。

互动接口：`PUT/DELETE /api/dramas/{id}/like`、`PUT/DELETE /api/dramas/{id}/favorite`、`GET /api/me/favorites`。

增强接口：`GET /api/me/history`、`PUT /api/dramas/{id}/progress`、`DELETE /api/me/history/{id}`、`POST /api/dramas/{id}/comments`。

管理接口：`GET /api/admin/stats`、`GET/POST /api/admin/dramas`、`PUT/DELETE /api/admin/dramas/{id}`。

| 新接口 | 权限与契约 |
| --- | --- |
| `GET /api/dramas/{id}/episodes` | 公开；按集号返回分集，登录后带本人的进度 |
| `PUT /api/dramas/{id}/episodes/{episodeId}/progress` | 登录；`{progressSec,durationSec}`，验证集属于剧，进度裁剪到时长 |
| `PUT/DELETE /api/dramas/{id}/follow` | 登录；幂等追剧和取消追剧 |
| `GET /api/me/following` | 登录；追剧片单、连载状态、新集及未完集数 |
| `PUT /api/admin/dramas/{id}/series` | 管理员；`{status,totalEpisodes}`，校验全集完整性 |
| `POST /api/admin/dramas/{id}/episodes` | 管理员；`{episodeNo,title,videoUrl}` |
| `PUT/DELETE /api/admin/dramas/{id}/episodes/{episodeId}` | 管理员；改集/删集，验证归属和至少保留一集 |

错误统一返回 `{ "message": "可读错误信息" }`，常用状态码为 400、401、403、404、409。

## 5. 前端结构

新增 `Player.tsx`（分集播放及视频生命周期）、`Following.tsx`（追剧片单）、`EpisodeManager.tsx`（分集后台）、`downloads.ts`（兼容旧缓存的分集键）及 `episodes.css`。播放器已从 `main.tsx` 抽出。

`main.tsx` 负责路由 hash、认证状态、发现/榜单/收藏/历史/后台视图；`Profile.tsx` 负责个人主页、资料编辑、片单搜索和管理；`ProfileImageEditor.tsx` 使用 Canvas 预览裁剪图片，支持指针拖动和可键盘操作的滑块。`Modal.tsx` 复用弹窗及焦点管理；`api.ts` 负责 Token 注入、中文网络错误转换和数量格式化；`style.css` 和 `profile.css` 提供桌面及手机布局。

移动端使用底部导航，播放器采用 `playsInline`，个人中心使用封面背景、圆形头像和收藏/观看记录 Tab。头像与背景通过同源 multipart 接口上传，后端统一缩放为 JPEG 并写入 `uploads/`；短剧分享 URL 为 `/#watch/{id}`；登录用户详情含个人进度，播放器在元数据加载后恢复位置，播放中定期同步。离线片库用本机 Cache Storage 和 `localStorage` 元数据，无需离线 API。

裁剪仅在确认保存时编码 JPEG（头像 512×512、背景 1600×900）并提交，取消只释放本地预览资源。服务端继续独立校验与重编码，不信任客户端文件类型。新地址保存成功后的旧文件清理失败只记录日志，不把已完成的上传返回为失败。Vite 开发代理包含 `/api` 和 `/uploads`，保证开发环境回显。

## 6. PWA 方案

`manifest.webmanifest` 设置名称、192/512px PNG 图标、`standalone` 显示模式和竖屏方向。Vite 生成 `asset-manifest.json`，`sw.js` 安装时预缓存 HTML、JS、CSS 等 App 壳资源；带哈希的构建资源优先读缓存，避免断网重载白屏。`mujian-app-v3` 升级仅清理旧 App 壳缓存，保留 `mujian-offline-v1`。视频和音频不自动写入 App 壳缓存，用户主动下载的媒体由独立缓存管理，支持 HTTP Range 206/416 和离线拖动；`/api/` 动态接口不缓存。认证网络错误不当作 401 清理 Token，重新联网后再恢复用户状态。

当前方案满足“可安装 App”体验，但不是原生安装包。要发布 APK/IPA，需要引入 Capacitor、Android/iOS SDK、签名和应用商店配置。

## 7. 验证与运行

新增 `scripts/verify-episodes.mjs` 验证 28 项分集接口规则，`scripts/verify-episodes-ui.mjs` 验证播控、追剧和后台，截图存 `docs/screenshots/episodes/`。2026-10-01 WSL 启动报告资源不足，本轮使用现有 Windows 脚本完成构建和真实 MySQL 验收，未宣称本轮 Linux 构建成功。

Linux 优先使用 `scripts/build.sh` 构建、`scripts/start.sh` 连接已有 MySQL 运行；Windows 本地演示保留 `scripts/build.ps1` 和 `scripts/start.ps1`。`scripts/verify.mjs` 执行 36 项 HTTP 验收，`scripts/verify-sw.mjs` 检查离线缓存与 Range，`scripts/verify-ui.mjs` 在真实浏览器检查完整用户流程与 390/320px 布局。截图见 `docs/screenshots/`。

`scripts/verify-profile.mjs` 另做 11 组资料与片单专项验收，涵盖服务端越权保护、图片和昵称错误、取消/失败重试、输出尺寸、刷新持久化、搜索、键盘操作和小屏布局。
