# 幕间需求实现映射与演示效果

本文把纸面方案、红果短剧公开产品能力和幕间当前代码逐项对齐，便于快速判断“需求是什么、用户能看到什么、由哪里实现、如何验收”。

## 完成度口径

| 标记 | 含义 |
| --- | --- |
| 已实现 | 当前版本有对应页面或接口，并纳入自动验收，或可直接在界面操作验证 |
| 部分实现 | 已落地可运行的基础版本，但与完整商业产品仍有明显差距 |
| 规划中 | 当前版本没有交付，不应在演示时描述成已完成 |

| React 前端 | 已实现：React 19、TypeScript、Vite | 桌面侧栏、移动底部导航、发现页、播放器、个人中心、管理页 | `frontend/src/main.tsx`、`frontend/src/style.css` | 打开 `http://127.0.0.1:8080` 操作页面 |
| MySQL 持久化 | 已实现：MySQL 8.4、JdbcTemplate、参数化 SQL | 账号、短剧、互动和观看进度重启后仍保留 | `backend/src/main/resources/schema.sql`、`backend/src/main/resources/application.yml` | `GET /api/health` 返回数据库连接状态 |

| 管理员短剧 CRUD | 已实现：管理员统计、新增、查询、编辑、删除；普通用户无权限 | 登录管理员后出现内容管理页和统计数据 | `AdminController.java`、`DramaRepository.java`、`frontend/src/main.tsx` | 普通用户得到 403；管理员完成新增、编辑、删除验收 |

## 红果竞品能力映射

竞品分析只依据公开信息提取常见产品模块，不代表红果内部实现。当前版本交付的是可演示的核心闭环，不等于复刻商业短剧平台的全部内容、算法和运营系统。

| 竞品模块 | 幕间状态 | 当前页面表现 | 差距或边界 |
| --- | --- | --- | --- |
| 推荐/发现首页 | 部分实现 | 精选首屏、分类、搜索和热门排序帮助用户开始找内容 | 当前无个性化推荐模型和用户画像 |
| 分类与榜单 | 已实现 | 分类筛选、人气榜单按播放量排序并显示名次 | 分类数量及榜单运营规则为演示规模 |
| 短剧详情和沉浸播放 | 部分实现 | 弹层播放器支持播放、拖动、互动及评论 | 当前是单视频短片，不含剧集目录、竖屏连播和下一集队列 |
| 搜索 | 已实现 | 可按标题搜索，并可与分类筛选组合使用 | 无搜索联想、热词和复杂排序 |
| 点赞、收藏、评论 | 已实现 | 播放器互动状态、我的收藏和剧友说评论区 | 无关注关系、评论审核工作台和举报闭环 |
| 观看历史与继续观看 | 已实现 | 展示最近观看和进度百分比，点击回到对应播放器 | 当前每条短剧对应一个视频，不存在跨分集续播 |
| 移动 App 使用体验 | 部分实现 | 自适应移动布局、底部导航、可安装 PWA、独立窗口 | PWA 不是应用商店发布的 Android/iOS 原生包 |
| 离线观看 | 部分实现 | 用户可手动缓存当前视频，Service Worker 缓存 App 壳 | 登录、列表和互动仍依赖服务端；浏览器存储受设备策略限制 |
| 会员、广告、付费、弹幕 | 规划中 | 当前没有对应入口或交易流程 | 不在当前版本范围 |
| 连载状态、追更提醒、消息推送 | 规划中 | 当前没有剧集发布日历和推送 | 需要剧集、发布计划和通知服务模型 |

竞品分析详见 [02-红果竞品分析.md](02-红果竞品分析.md)。

## 创新点与验证

| 幕间设计 | 解决的问题 | 当前做法 | 当前边界 |
| --- | --- | --- | --- |
| 心情选剧 | 用户不想输入关键词时的选择疲劳 | 从当前列表随机挑选一部并打开播放器 | 不是 AI 推荐，也没有个性化偏好学习 |
| 继续观看 | 用户中断后难以找回内容 | 登录用户在暂停/结束时保存观看位置，并在历史页显示进度 | 单视频粒度，当前不支持剧集级观看队列 |
| 透明片源说明 | 避免把测试素材误认为商业短剧 | 播放器显示 Sintel、Blender Foundation 与 CC BY 3.0 署名 | 8 条演示内容共用同一片源，不是版权内容库 |
| 可安装 PWA | 快速体验 App 形态，减少安装门槛 | Web App Manifest、Service Worker、添加到桌面及移动导航 | 未生成签名 APK/IPA，离线能力不覆盖全部在线业务 |

## 数据表与业务约束

| 数据表 | 作用 | 关键约束 |
| --- | --- | --- |
| `user` | 账号、密码哈希、昵称、角色 | 用户名唯一；角色仅允许 `USER` 或 `ADMIN` |
| `drama` | 短剧标题、封面、简介、视频地址、分类和播放量 | 播放量非负 |
| `user_favorite` | 用户收藏关系 | `(user_id, drama_id)` 联合唯一，用户或短剧删除时级联清理 |
| `user_like` | 用户点赞关系 | `(user_id, drama_id)` 联合唯一，用户或短剧删除时级联清理 |
| `watch_history` | 用户最近观看时间与播放位置 | `(user_id, drama_id)` 联合唯一，进度和时长非负 |
| `drama_comment` | 用户对短剧的评论 | 评论最多 500 字，关联删除时级联清理 |

## 自动验收证据

从项目根目录运行：

```powershell
node scripts\verify.mjs
```

脚本会访问本机运行中的服务并执行 34 项自动检查。覆盖数据库连接、公开列表、注册登录、BCrypt/JWT 行为、管理员权限、短剧 CRUD、资源地址校验、点赞收藏重复与并发、观看进度、评论、视频 Range、首页以及 PWA manifest/Service Worker。临时验收数据会在脚本结束时清理。

完整构建和启动步骤见 [README.md](../README.md)；验收逻辑见 [verify.mjs](../scripts/verify.mjs)。自动接口验收不替代不同设备和浏览器上的人工视觉检查。

## 建议现场演示顺序

1. 打开发现首页，先看精选首屏、短剧卡片和心情选剧。
2. 搜索“雨停”并切换分类，说明内容来自后端查询。
3. 播放几秒后点赞、收藏并发表评论，再暂停保存进度。
4. 打开继续观看和我的收藏，展示进度回访与互动持久化。
5. 介绍 PWA 添加到桌面和离线缓存入口，并说明它不是原生安装包。
6. 使用 `admin` / `Admin123!` 打开内容管理，演示统计和短剧 CRUD。
7. 最后说明数据库联合唯一约束、管理员权限、BCrypt 密码哈希，以及演示内容和后续规划的边界。
