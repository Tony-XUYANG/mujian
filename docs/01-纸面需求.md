# 纸面需求基线

## 1. 文档定位

本文件整理用户提供的纸面说明，作为本项目的原始需求基线。纸面说明中的产品设想、技术栈和开发流程属于项目约束；其中关于 Codex 的提示词和现场话术属于研发协作与演示要求，不是运行时功能。

本次用户追加的要求另行记录在总需求中：产品必须有 App 形态；需要分析红果短剧并覆盖竞品已经验证的核心模块；在覆盖基础能力的同时加入可解释的创新；交付产品、需求 Markdown 和技术架构 Markdown。

## 2. 产品范围

项目名称：幕间，简化版短剧 Web App。

目标：提供短剧浏览、播放、互动和后台内容管理的可运行演示产品。

原始技术栈：Java + Spring Boot、React、MySQL，使用 Codex 辅助样板代码编写。

纸面要求的四张核心业务表：

| 表 | 关键字段 | 约束 |
| --- | --- | --- |
| `user` | `id`、`username`、`password`、`nickname`、`create_time` | 用户名唯一；密码 BCrypt 加密 |
| `drama` | `id`、`title`、`cover_img`、`description`、`video_url`、`view_count`、`create_time` | 保存短剧内容和播放计数 |
| `user_favorite` | `id`、`user_id`、`drama_id` | `(user_id, drama_id)` 联合唯一 |
| `user_like` | `id`、`user_id`、`drama_id` | `(user_id, drama_id)` 联合唯一 |

点赞和收藏使用关联表，避免把多值关系直接塞入用户或短剧主表。联合唯一约束负责数据库级防重复，服务层保证幂等响应。

## 3. 功能模块

后端模块：

1. 用户注册、登录、BCrypt 密码校验和 Token 返回。
2. 短剧公开列表、详情和视频播放。
3. 点赞、取消点赞、收藏、取消收藏。
4. 管理员短剧新增、编辑、删除和查询。
5. 全局异常、参数校验、权限、跨域/同源访问配置。

前端页面：

1. 登录/注册。
2. 首页短剧列表，展示封面和标题。
3. 详情/播放器，支持点赞和收藏。
4. 管理后台，提供短剧 CRUD 表单和列表。

## 4. 原始开发顺序

数据库建表 → 后端实体/Mapper → 后端接口 → Postman 测试 → React 页面 → 前后端联调 → 整体演示。

顺序的目的，是先固定业务规则和接口契约，再让前端消费稳定接口，缩小联调故障范围。

## 5. Codex 协作边界

人负责产品、表结构、架构、权限、校验和边界逻辑；Codex 负责小块样板代码，例如实体、CRUD 模板、React 组件骨架和 axios 封装。

每次请求应携带技术栈、表结构和当前模块，只生成一个小功能。代码生成后必须核对字段、SQL、权限和错误处理。重点人工检查：重复点赞/收藏、密码是否明文、管理员权限、外键清理、错误状态码和资源地址校验。

遇到编译或运行错误，可以将完整堆栈交给 Codex 定位，但修复后仍需要本地构建和接口验收。

## 6. 原始验收

- 注册和登录成功，密码不以明文落库。
- 公开列表和详情可访问，视频可以播放和拖动。
- 登录用户可以点赞/取消点赞、收藏/取消收藏。
- 重复互动不会增加重复关系记录。
- 普通用户不能调用后台管理接口。
- 管理员可以完成短剧 CRUD。
- 前后端联调可完成一次完整演示。

## 7. 与本次追加需求的关系

纸面需求定义了最小业务闭环；本次增强在其上增加观看历史、评论、PWA 安装和离线缓存、移动端底部导航、个人中心、继续观看和“心情选剧”。增强内容不删除四张核心表，而是使用独立关系表承载新增行为。
