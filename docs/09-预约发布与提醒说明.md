# 预约、发布计划与站内提醒

这次把“看到连载 → 预约下一集 → 到期发布 → 收到提醒 → 播放新集”接成可操作流程。界面、后台接口和 MySQL 数据均已实现；没有用静态成功提示代替预约或发布。

## 用户入口

“我的追剧”分为正在追、更新日历、我的预约三个页签。更新日历游客可用，按北京时间分组，可搜索剧名/分集标题，也可只看未来七天。预约需要登录；登录后保留日历位置。相同用户重复预约只保留一条关系。

“我的预约”展示待更新、已上线、已取消三种状态。改期后显示新的时间；上线后出现“观看新集”，直达该集而不是默认回到第一集。已发布集下架后显示“本集已下架”。取消预约可以移除该条目，不影响收藏或观看进度。

右上角铃铛打开“更新提醒”，有未读数字、全部/未读筛选、20 条一页、单条和全部已读。点击提醒同时标记已读并打开对应新集。提醒与播放进度是两个独立状态：已读表示看过提醒，不等于看完视频。

## 追剧与预约有什么区别

| 操作 | 含义 | 上线时接收范围 |
| --- | --- | --- |
| 追剧 | 关注一部剧之后的更新 | 发布当时仍在追剧的人 |
| 预约 | 等待一个明确的未来分集 | 发布当时仍预约该计划的人 |
| 收藏 | 把已上架短剧放进片单 | 单独收藏不会产生更新提醒 |

同一个人同时追剧和预约，只收到一条新集提醒。仅取消预约但保留追剧，仍会收到追剧更新；仅取消追剧但保留预约，仍会收到该集的预约提醒。取消两种关系才会退出该集的后续收件范围。已发出的提醒不会因为取消关系而撤回。

## 管理后台

管理员打开“内容管理 → 某部剧的分集 → 发布排期”。填写集号、标题、片源和北京时间，可安排未来一年以内的新集。新计划会在用户日历出现，但发布前不会加入播放目录。

| 操作 | 结果 |
| --- | --- |
| 保存新排期 | 校验与已发布/有效排期不重号；必要时扩大总集数，短剧恢复连载 |
| 修改排期 | 修改标题、片源或时间，保留原预约；不能替换原集号 |
| 取消排期 | 二次确认后停止自动发布；用户预约中显示已取消 |
| 恢复排期 | 编辑已取消计划，给出新的未来时间后保存，原预约继续有效 |
| 立即发布 | 二次确认后创建正式分集并生成站内提醒；重复操作不会再次发布 |
| 修改已发布内容 | 回到上方分集列表编辑；不会重复生成上线提醒 |

存在有效排期时不能标记完结，总集数不能小于排期最大集号。已有“新增分集 → 保存分集”入口仍用于立即上线，也会给追剧用户发提醒。该入口不能抢占一个已排期的集号。

## 时间、持久化与一致性

数据库保存 Unix 毫秒，日期输入和显示固定为北京时间。自动化浏览器使用洛杉矶时区，已验证页面仍显示正确的北京时间。

服务启动约 5 秒后扫描到期计划，随后每 10 秒扫描一次，每批最多 50 条。服务停机时无法发布；重新启动后会扫描补发。上线时间是目标时间，少量扫描延迟正常，积压和失败重试可能进一步延迟。

所有关键操作先锁定短剧，再锁计划；冲突检查使用数据库当前读。发布事务同时创建分集、更新计划状态、调整连载信息和写入提醒，中途失败整体回滚，计划留待下一轮重试。并发立即发布、定时扫描不会生成重复集；恢复已取消排期与新增同集排期并发时，只允许一个有效计划成功。

用户关系采用联合主键，提醒采用用户/分集唯一约束。信箱接口始终使用 JWT 中的身份；不能访问或标记其他账号的提醒。“全部已读”携带加载时的消息 ID 上界，因此操作过程中刚到的新提醒会保留未读。

日历、个人预约、信箱及未读数在页面可见且联网时每 30 秒刷新，回到窗口或重新联网也刷新，并有手动刷新按钮。网络失败显示中文原因，支持重试。动态接口不会写入 PWA 离线缓存。

## 演示步骤

1. 用普通账号打开“我的追剧 → 更新日历”，预约“第七封来信”的待更新集。
2. 在另一浏览器会话使用管理员账号，打开该剧“分集 → 发布排期”。可以先改期，回到普通账号刷新确认时间同步。
3. 管理员点“立即发布”并确认。也可设置未来几分钟，等服务自动发布。
4. 普通账号刷新信箱或等待页面轮询，看到一条新集提醒。点击后应打开对应的第几集，未读数减少。
5. 在后台尝试重复发布、给已有集号创建排期或用普通账号调用管理接口，确认冲突/权限校验。

示例计划仅在首次升级初始化一次，时间为初始化次日/后日 20:00。若示例集已上线，后台可以创建新的演示集计划。示例章节共用 Sintel 视频，功能不代表新增了商业短剧片源。

当前只支持已上架短剧的未来分集预约，尚未支持整部未上架新剧的首播预约。没有独立草稿状态，保存排期后即公开标题和时间；仅片源地址留在管理接口中。改期、取消通过预约列表展示，不另发事件消息。站内提醒不会在关闭 App 时弹出系统通知。

当前日历/个人预约最多返回 200 条；信箱使用分页。大规模收件人分批通知、发布失败的运营工作台、退避/死信、Web Push、原生推送、整剧首播和签名 APK/IPA 均在后续总需求与架构中列为未完成项。
