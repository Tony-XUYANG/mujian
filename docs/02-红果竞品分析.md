# 红果短剧竞品分析

## 1. 分析边界

本文件是基于公开页面和公开应用信息做的产品分析，不代表红果内部实现，也不把第三方页面的宣传文案当作幕间已经拥有的能力。分析目标是提取用户已经熟悉的短剧产品模块，用于确定幕间的演示优先级。

公开参考（2026-09-29 核对）：

- [红果短剧 App Store 官方产品页](https://apps.apple.com/cn/app/id6451407032)：产品介绍列出单列推荐、剧场九宫格、评论、一键追剧、提前预约、任意选集、小窗、倍速，以及电影、小说、听书、漫画和会员等业务。下表只按此公开描述判断，不推测内部实现。

## 2. 竞品能力拆解

| 能力 | 用户价值 | 幕间的实现判断 |
| --- | --- | --- |
| 单列个性化推荐 | 上下滑找剧、降低选择成本 | **未实现**；现有精选首屏和随机选剧不能等同个性化单列流 |
| 剧场九宫格、分类和热榜 | 按兴趣或热度发现内容 | **部分实现**：分类、卡片网格和播放量榜单；不是九宫格剧场 |
| 竖屏/沉浸式播放 | 适配移动端连续观看 | **部分实现**：移动端播放器和 PWA 独立窗口；目前是横屏单视频素材 |
| 任意选集、全集连看 | 减少手动找下一集的操作 | **未实现**：没有分集目录和连播队列 |
| 热播、完结/连载状态 | 帮助用户判断内容是否值得追 | 当前用精选短片标签，状态模型列入后续 |
| 搜索 | 直接定位短剧 | 已实现标题搜索 |
| 播放进度 | 离开后继续观看 | **已实现单视频续播**：登录后定期同步进度并恢复位置 |
| 一键追剧、点赞和评论 | 表达偏好并参与社区 | **部分实现**：收藏、点赞和剧友评论；没有连载追更状态 |
| 小窗与倍速播控 | 适应碎片时间和不同节奏 | **部分实现**：浏览器原生视频进度控制；独立小窗和倍速 UI 未实现 |
| 免费内容入口 | 低门槛开始使用 | 当前演示内容标记为免费观赏 |
| 移动端 App 体验 | 更适合碎片时间使用 | **部分实现**：可安装 PWA、底部导航和离线片库；不是原生 APK/IPA |
| 提前预约/上线提醒 | 待上架内容上线时回访 | **未实现**：依赖内容状态、预约关系和通知服务 |
| 小说、听书、漫画、会员 | 扩展内容消费与商业模式 | **未实现**：不属于当前短剧演示内容库 |

## 3. 竞品启发与差异化

竞品已经验证的基本路径是：推荐内容 → 快速播放 → 连续观看 → 互动沉淀 → 回到个人内容。幕间优先实现这条闭环，不把复杂推荐算法或商业化支付伪装成已完成能力。

幕间的差异化创新：

1. **心情选剧**：用户不想输入搜索词时，基于当前片库随机挑选一部，减少选择疲劳。后续可以升级为标签和情绪偏好的可解释推荐。
2. **继续观看 + 进度云同步**：播放中约每 15 秒及暂停/结束/关闭时保存，重新打开恢复到上次位置。
3. **剧友评论**：评论与单集短片绑定，先做轻互动，再为后续剧集讨论和内容审核留出扩展点。
4. **离线片库 PWA**：添加到桌面后可从离线片库管理手动保存的视频，断网后重启并拖动播放；在线业务仍需网络。
5. **透明内容提示**：演示片源明确标注 Sintel/Blender Foundation/CC BY 3.0，避免把示例素材描述成商业版权内容。

## 4. 暂不照搬的能力

完整剧集和多集连播、复杂推荐算法、广告/会员/付费解锁、弹幕、实时直播、追更日历和消息推送，都需要内容、运营或基础设施配合。它们属于后续产品阶段，不应在当前演示中虚构。

## 5. 竞品结论

当前版本应以“可安装的短剧 App 闭环”为核心：能发现、能播、能互动、能回来继续看、能由管理员维护内容。下一阶段的主要增量不是继续堆页面，而是增加分集数据模型、内容状态和推荐解释能力。
