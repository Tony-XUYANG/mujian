# 幕间增强后总需求

## 1. 目标

交付一个“红果核心体验 + 幕间轻创新”的短剧 App 演示版本：用户打开就能发现内容，点击即可播放，互动和进度可以沉淀，下一次能继续观看；管理员可以维护内容和查看基础运营数据。

## 2. 产品原则

1. 先保证发现、播放、互动、回访的主链路完整，再增加复杂能力。
2. 人决定内容规则、权限和数据模型，AI 只生成可审查的小块样板代码。
3. 任何演示素材、版权、推荐和商业化边界都明确标注，不用功能假象替代真实能力。

## 3. 目标模块

### 用户端 App

- 发现首页：精选、分类、搜索、最新/热门排序。
- 人气榜单：按播放量排序并显示名次。
- 播放器：播放、拖动、点赞、收藏、评论、分享和离线缓存。
- 继续观看：历史、进度百分比、最近观看和删除历史。
- 我的：账号、收藏、观看记录、安装入口、在线状态和同步提示。
- 心情选剧：基于当前内容库的随机选剧入口，后续可接标签偏好。

### 内容管理

- 管理员登录和角色隔离。
- 内容统计：短剧数、用户数、播放量、收藏数。
- 短剧新增、编辑、删除、搜索。
- 封面和视频资源地址校验。

### 平台能力

- BCrypt 密码、8 小时 JWT、无状态鉴权。
- 统一错误响应、参数校验、外键级联。
- PWA manifest、Service Worker 和移动端布局。

## 4. 用户故事

- 游客可以搜索“悬疑”，打开一部短剧并查看评论。
- 用户注册后点赞、收藏，刷新或重新登录仍能看到状态。
- 用户播放到一半退出，下一次从“继续观看”回到历史位置。
- 用户不想搜索时点击“心情选剧”，直接获得一部可看的故事。
- 管理员新增一部短剧后，发现页可以立即看到；删除后互动关系被清理。
- 手机用户将幕间添加到桌面，在网络不稳定时仍能打开 App 壳和已缓存视频。

## 5. 分阶段路线

### 当前交付（P0）

上述用户端、后台、六张表、PWA 和 34 项自动验收。

### 下一阶段（P1）

增加 `drama_episode`、剧集状态、更新计划和连播队列；将心情选剧从随机升级为基于分类/时长/观看历史的可解释规则；增加评论举报和管理员审核。

### 商业化阶段（P2）

接入对象存储、转码/CDN、会员和广告、消息推送、数据看板、原生壳发布。该阶段需要新的安全、版权、支付和运营设计。

## 6. 验收标准

- 桌面端和移动端无明显横向溢出，底部导航可用。
- 未登录用户不会调用需要身份的互动接口。
- 普通用户访问后台返回 403，过期 Token 返回 401。
- 重复和并发点赞/收藏最终各只有一条关系。
- 评论、历史和进度可以真实写入并重新读取。
- PWA manifest、Service Worker 和 App 壳可访问。
- `npm run build`、`mvn -q -DskipTests package` 和 `node scripts/verify.mjs` 通过。

## 7. 内容与交付边界

当前 8 条短剧标题和简介为演示文案，共用 Sintel Trailer 片源。不能将其宣传成完整商业短剧库，也不能宣称已经生成 APK/IPA。PWA 是当前可安装 App 交付形态。
